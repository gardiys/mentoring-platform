# Подсчёт собеседований в эффективности менторов

Проверка 11 сентября 2026 года обнаружила разные группы в одной ячейке:
`recording_count` учитывал записи всех учеников ментора, а `recording_students` —
только учеников с текущим статусом `interviewing`. Поэтому переход на испытательный
срок скрывал ученика из счётчика, хотя записи оставались. Среднее число этапов также
использовало только текущую группу `interviewing`, хотя рядом показывался общий итог.

В таблице учитываются только текущие статусы `learning` и `interviewing`.
Ученики в статусе `learning` с этапами/записями участвуют в статистике, даже если ментор
ещё не переключил статус. `probation` и `finished` исключены из всей выборки: количества
учеников, этапов, записей, AI-разборов, офферов, ближайших этапов и знаменателей процентов.
Это правило применяется также к ученикам без ментора и периоду «всё время».

Показатели для каждого ментора внутри этой выборки:

| Поле | Правило |
| --- | --- |
| `assigned_students` | Его ученики в статусах `learning` и `interviewing` |
| `students_with_interviews` | Из них — ученики хотя бы с одним этапом за период |
| `interview_count` | Все этапы этих учеников за период |
| `recording_count` | Этапы за период с прикреплённой записью (`media_storage_key`) |
| `recording_students` | Уникальные ученики хотя бы с одной такой записью |
| `recording_participation_percent` | `recording_students / students_with_interviews × 100` |
| `average_interviews_per_active_student` | `interview_count / students_with_interviews` |
| `interviewing_students` | Ученики с текущим статусом `interviewing` |
| `active_interviewing_students` | Из текущего статуса `interviewing` — ученики с этапами за период |
| `participation_percent` | `active_interviewing_students / interviewing_students × 100` |
| `inactive_interviewing_students` | Текущий статус `interviewing`, но этапов за период нет |

При нулевом знаменателе доля и среднее равны нулю. В интерфейсе общий счётчик
учеников с этапами отделён от активности внутри текущего статуса. Общая карточка
учеников с этапами включает и учеников без ментора; строки таблицы — только назначенных.

Период — скользящие последние 7/30 дней или всё время до текущего момента. Для этапов
и записей используется `scheduled_at`, для AI — `ai_analysis_requested_at`, для офферов —
`offer_received_at`. Будущие этапы исключаются из прошедших и отдельно показываются в
планах на 7 дней. Дата добавления этапа и дата загрузки не заменяют дату собеседования.
Отдельная историческая дата загрузки записи в этой модели не хранится.

Запись не требует успешного AI-разбора или публикации в каталоге. Закрытый процесс
собеседований сохраняет свои этапы в статистике. Удалённые этапы/записи не учитываются.
Мок-собеседования в эту таблицу не входят. Прошедшая дата этапа — сигнал активности,
но отдельного подтверждения фактического посещения эта формула не проверяет.

Фильтры направления и доступа учеников действуют на всю группу. По умолчанию интерфейс
выбирает учеников с открытым доступом и последние 7 дней. Назначение ментора и учебный
статус берутся текущие; при наличии `StudentMentorshipState` его статус имеет приоритет
перед старым полем `MentorStudent.learning_status`.

## Проверка рабочих данных (только чтение)

У `@Olmec0` (в базе Максим Кузнецов, ментор Роман Мамин) найдены две записи к этапам
20 и 21 августа: они попадают в 30 дней и всё время, но не в неделю на дату проверки.
У двух этапов 10 сентября записи отсутствуют. Этапы, внесённые 9 сентября задним числом,
считаются по их фактической указанной дате.

За неделю у учеников Романа Мамина с открытым доступом обнаружены 2 этапа без записей
у одного ученика `interviewing` и 4 этапа с записями у одного ученика `probation`.
Старая формула давала 4 записи и 0 учеников с записями. По уточнённому правилу ученика
`probation` исключаем целиком: остаются 2 этапа, 1 участник и 0 записей,
среднее — 2 этапа на участника.
Активность внутри статуса `interviewing` при этом остаётся 1 из 3 назначенных учеников
с таким статусом, если назначения и статусы не изменились относительно снимка таблицы.

Для обновления нужны backend и frontend; миграция БД и пересчёт сохранённых разборов
не требуются. Статистика вычисляется при запросе. Кнопка «Обновить статистику» повторяет
запрос с выбранными фильтрами без перезагрузки страницы.
