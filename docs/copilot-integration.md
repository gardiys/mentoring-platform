# Interview Copilot

Copilot использует `https://copilot.codewaste.ru`, платформа — `https://platform.codewaste.ru`. Оба приложения находятся на одном сервере за существующим Caddy. В `infra/Caddyfile` добавлен блок Copilot с upstream `copilot-api:8001`; контейнер Copilot подключается к сети `mentoring-platform-production_edge`. Backend и база Copilot не публикуют порты на хост.

## Вход

Добавлены маршруты `/api/v1/auth/desktop/start`, `/authorize`, `/token`, `/logout`. Desktop начинает пятиминутный запрос и открывает системный браузер. Обычная web-сессия ученика подтверждает доступ с проверкой кода, Origin и подписанного CSRF. Browser cookie не передаётся приложению. Desktop получает отдельный opaque Bearer `copilot_` токен; платформа хранит только хеши polling-secret и токена.

`DESKTOP_AUTH_ENABLED` включает механизм (по умолчанию true). `DESKTOP_ACCESS_TOKEN_TTL_SECONDS` задаёт срок токена (по умолчанию 86400, от часа до семи дней). Refresh не предусмотрен: после истечения срока нужно войти снова. Получить токен по одобренному запросу можно один раз.

Доступ разрешён только активному ученику: GET `/api/v1/me`, база знаний, база вопросов, собственный опубликованный карьерный пакет и POST собственного desktop-logout. Остальные API недоступны этому токену. Блокировка пользователя, смена `session_version` и выход из Copilot отзывают соответствующий доступ. Cookie и Telegram initData сохраняют существующее поведение.

## Материалы и миграция

Copilot явно синхронизирует доступные ученику знания, вопросы выбранного трека и, с отдельным согласием, опубликованное резюме через API. К БД платформы он не подключается. Автоматической отправки фидбека или изменений roadmap нет.

Перед обновлением backend примените Alembic `20260907_0082` (новая таблица `desktop_grants`). В production Compose настройки desktop передаются backend; миграция запускается сервисом `migrate`. Существующий Telegram web login должен быть настроен.

Полный порядок обновления обоих проектов, DNS, прокси и Caddy находится в соседнем `mentoring-copilot/docs/deployment.md`. Серверный прокси пользователь задаёт отдельно в `.env.production` Copilot.

## Проверки

`tests/test_desktop_auth.py` проверяет подтверждение, CSRF/Origin, ограничение частоты polling, одноразовую выдачу, scope, срок действия, блокировку и отзыв. Вместе с `tests/test_web_auth.py` выполнено 11 тестов. Миграция проверена на отдельной тестовой БД. Дополнительно пройден вход, импорт и отзыв через два локально запущенных API с синтетическим учеником; production DNS и сертификат этим не проверялись.


## Раздел Copilot и закрытые загрузки

Страница `/copilot` добавлена в меню только для `admin`. Ученик и ментор не видят пункт меню и получают отказ при прямом переходе. Backend независимо проверяет администратора в `GET /api/v1/copilot/releases` и `GET /api/v1/copilot/releases/{asset_id}/download`. Гостям возвращается 401, ученикам/менторам — 403. Desktop-токены также не дают доступа к этим маршрутам. Ограничение действует на раздел и файлы, а не только на кнопку в интерфейсе.

На странице есть краткое описание помощника, инструкция и три установщика версии 0.1.0: macOS Apple Silicon (DMG), macOS Intel (DMG), Windows x64 (EXE). Файлы загружаются с авторизацией платформы, прогрессом, отменой и обработкой ошибки. Текущие сборки помечены как тестовые без подписи разработчика.

Файлы находятся в `.local/copilot-releases/`, исключены из Git и не помещаются в публичный frontend. Compose монтирует каталог в backend только для чтения: `/var/lib/mentoring/copilot-releases`. `COPILOT_RELEASES_HOST_DIR` меняет путь на хосте, `COPILOT_RELEASES_DIR` — путь внутри backend. При запуске Python непосредственно из `backend/` путь по умолчанию `../.local/copilot-releases`.

### Обновление установщиков

После сборки в корне соседнего `mentoring-copilot`:

```bash
.venv/bin/python scripts/publish_platform_releases.py
```

Команда проверяет наличие трёх файлов, копирует их в `.local/copilot-releases` платформы, вычисляет SHA-256 и атомарно обновляет `manifest.json`. Имена включают хеш содержимого: новые сборки не перезаписывают файлы текущих загрузок. Старые файлы автоматически не удаляются. Для другого каталога используйте `--output /path/to/copilot-releases`.

Для production перенесите весь каталог `.local/copilot-releases/` на сервер в корень платформы (включая `manifest.json`). Этот шаг отдельный от Git: бинарники не входят в исходный код и Docker build context. Файлы должны быть доступны контейнеру на чтение; publisher устанавливает `0644`. Доступ пользователей к скачиванию проверяется API.

В корне платформы на сервере после переноса кода и файлов:

```bash
docker compose --env-file .env.production -f infra/docker-compose.prod.yml build backend frontend
docker compose --env-file .env.production -f infra/docker-compose.prod.yml up -d --no-deps backend frontend
```

Для самого раздела новые миграции не нужны. Если ранее не развёрнут desktop login, выполните также миграцию 20260907_0082 по инструкции интеграции. Страница загрузок сама по себе не включает сервис Copilot для учеников. В этой реализации открытие раздела ученикам требует отдельного изменения правил доступа; флага, который случайно откроет файлы, нет.

Проверка: зайти администратором на `/copilot`, скачать файл, затем открыть тот же адрес учеником и убедиться в отказе. Локально пройден настоящий browser-download Windows-установщика с проверкой SHA-256, три ширины экрана (1440/1024/390), прямой переход ученика, анонимный запрос и серверные проверки всех ролей/Range/отсутствующих файлов/выхода за каталог.


Результаты проверки раздела: 15 backend-тестов (закрытые сборки + desktop/web auth), 23 целевых frontend-теста, TypeScript, ESLint, Ruff/Mypy и production frontend build — passed. Полный параллельный frontend-прогон: 256/257; существующий тест редактирования карточки достиг таймаута около 5 секунд. Его файл отдельно прошёл 22/22 без изменений кода карточек. Браузерный сценарий из `mentoring-copilot/scripts/platform_page_review.mjs` проверил настоящий установщик, его хеш, отсутствие обрезанных кнопок и закрытый доступ. Рабочие данные пользователей при проверках не менялись.
