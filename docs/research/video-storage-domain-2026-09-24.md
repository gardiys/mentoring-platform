# Отказ воспроизведения видео: переезд домена FirstVDS

24 сентября 2026 года проверена выдача видео на рабочем сервере без изменения
конфигурации, БД или файлов. Контейнеры работали, API каталога возвращал 200,
а маршрут воспроизведения — 307 на подписанную ссылку хранилища.

Причина: `s3.firstvds.ru` не разрешался в DNS. Это воспроизвелось в backend-контейнере
и на локальной машине. В production оба S3 endpoint содержали старый домен;
архивный S3-клиент также использовал его как константу.

FirstVDS [объявил переход на firsts3.ru 27 августа 2026 года](https://firstvds.ru/blog/vazhnoe-obnovlenie-s3-pereezzhaet-na-novyy-domen-firstvds).
Перенаправление на новый домен не помогает, когда старый уже не разрешается в DNS.
Подписывать S3-запрос нужно сразу для нового адреса, до формирования URL.

В отдельном диагностическом процессе endpoint был заменён только в памяти.
На тех же объектах проверены GET-запросы `Range: bytes=0-63`:

| Записи | Количество | Старый домен | Новый домен |
| --- | ---: | --- | --- |
| Новые собеседования | 2 | Ошибка DNS | 206, video/mp4, 64 байта |
| Импортированные собеседования | 2 | Ошибка DNS | 206, video/mp4, 64 байта |
| Учебные видео | 2 | Ошибка DNS | 206, video/mp4, 64 байта |

Подписанные ссылки, секреты и содержимое файлов в вывод не включались.
Проверка подтверждает доступность объектов и частичную выдачу; полноценное
воспроизведение в пользовательском браузере не проверялось.

## Локальное исправление

- Нормализация старого HTTPS endpoint FirstVDS в настройках перед созданием
  внутренних и публичных S3-клиентов; остальные провайдеры не меняются.
- Архивный клиент подписывает запросы на `https://firsts3.ru`, сохраняя bucket,
  ключ объекта, HTTPS и авторизацию. Старые ссылки в БД остаются рабочими.
- Плееры различают сетевую ошибку и ошибку декодирования. Код браузера
  `MEDIA_ERR_SRC_NOT_SUPPORTED` больше не трактуется как доказательство того,
  что файл доступен и проблема только в кодеке.
- README и пример production-настроек указывают актуальный домен.

Изменения подготовлены для доставки через Git. Production не обновлялся.
После обновления нужно пересобрать backend и worker-контейнеры, использующие S3,
а также frontend для исправленного сообщения, и заново открыть запись.
Миграция базы и повторная загрузка видео не требуются. Совместимость позволяет
запуститься со старым `.env`, но для внешних CLI-инструментов в обоих S3 endpoint
следует явно указать `https://firsts3.ru`.

## Проверки

18 тестов миграции endpoint и подписания URL прошли без сетевых вызовов.
В наборе backend-проверок внешних записей, каталога, учебных материалов и настроек
прошли ещё 64 теста. Один общий тест инвентаризации авторизации
`test_every_api_route_has_authentication_or_an_explicit_public_contract` падает
на маршрутах Desktop/Copilot; тот же сбой подтверждён в изолированной копии
приложения с исходными `config.py` и `uploads.py` из HEAD, без данного исправления.

Прошли 32 frontend-теста, TypeScript, ESLint, Ruff, mypy для изменённых backend-модулей
и проверка diff. Тестовая PostgreSQL-база была отдельной и временной.
