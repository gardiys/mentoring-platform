# Дубли карточек, сообщения пользователей и видео на iPhone

Дата: 30 сентября 2026. Изменения подготовлены локально; рабочая система не изменялась.

## Почему список дублей не появлялся

В журнале ядра production подтверждены повторные OOM-kill процесса `arq` в maintenance-контейнере с лимитом 768 МиБ. Воркер перезапускался во время расчёта; Redis не получал готовый результат, интерфейс продолжал показывать формирование. На момент проверки опубликовано 2389 карточек, сохранённые векторы есть у 2379 (256 измерений); подтверждённых алиасов — 773. Средний ответ — 1885 байт.

Старый снимок включал полный вопрос и ответ для каждой пары. Даже после устранения повторов сборка целого JSON перед сжатием создаёт большой временный пик памяти. Новый формат v3 хранит карточку один раз и сжимает JSON последовательно. При чтении пары используют общие объекты карточек. Из записей алиасов больше не загружаются ответы и другие неиспользуемые поля. Нормализация текста и лексические признаки кэшируются с ограничением размера.

Фоновая задача продлевает блокировку во время работы. Перехватываемые ошибки сохраняются отдельно, отображаются пользователю и не провоцируют немедленный повтор на каждом опросе страницы; ручной повтор доступен. Старый результат сохраняется при ошибке обновления. OOM/SIGKILL невозможно перехватить в Python: оставшиеся блокировки истекают по TTL.

## Поиск по смыслу

Раньше векторы сравнивались только после отбора пар с общими словами. Теперь независимый поиск ближайших соседей использует сохранённые векторы карточек и подтверждённых формулировок. Сравнение выполняется блоками по 64 вектора; полная квадратная матрица не создаётся. До 12 разных карточек-соседей для каждой формулировки, порог cosine 0.72. Лексический и точный поиск сохранены.

Проверяются направление, модель, размерность, хеш исходного текста и корректность чисел. Отсутствующие или устаревшие векторы не используются; такие карточки остаются доступны лексическому поиску и пользовательским сообщениям. Генерация векторов остаётся в существующем AI-процессе: пересчёт дублей не вызывает платные API.

Сходство — кандидат для решения администратора, не доказательство тождественности. Автоматического объединения нет. Регрессионный тест с формулировками «Почему решил поменять работу?» / «Почему вышел на рынок?» проверяет отбор без общих значимых слов на синтетических векторах, а не качество внешней embedding-модели.

## Сообщения пользователей

Кнопка «Сообщить о дубле» доступна в таблице, карточках повторения и результатах поиска. Проверяются публикация карточки, направления и доступ пользователя. Повторная отправка одним пользователем идемпотентна.

Администратор видит сообщения в разделе дублей независимо от состояния автоматического снимка, ищет вторую карточку по тексту/ID в том же направлении и открывает существующее сравнение ответов. Объединение сохраняет журнал, появления вопроса и учебный прогресс; сообщения по объединённым карточкам закрываются в той же транзакции. Сообщение можно отклонить. Нужна миграция `20260930_0095`.

## Видео Telegram Mini App на iPhone

Для технической записи каталога `e206f663-0021-441e-a6df-29da806c298f` read-only проверка S3/ffprobe выявила Matroska под именем/MIME MP4. Кодеки H.264/AAC корректны, Range работает (206), авторизация проходит.

При первом открытии такого файла читается заголовок, создаётся проверенная MP4-копия с Fast Start через stream copy. Исходный объект не перезаписывается; повторные открытия используют копию. Ограничены размер, время и временное дисковое пространство. Добавлен `playsInline` в плеер каталога. Код не исправляет произвольные неподдерживаемые кодеки и не запускает массовое перекодирование.

## Проверки

- Backend: права доступа, повторная отправка, поиск, объединение, закрытие сообщения, сохранение прогресса; отдельные регрессии AI-модерации.
- Поиск: смысловая пара, разные модели/направления, устаревшие и повреждённые векторы, исключение рассмотренных пар, сериализация без копирования ответов, обработка ошибок фонового расчёта.
- Нагрузка: 2400 синтетических карточек, векторы 1536 измерений, длинные ответы; около 112 тысяч пар, полный цикл около 11 секунд, пиковая память 637 МиБ. Это локальный замер, не гарантия времени на production. Первоначальный вариант с монолитной сериализацией превышал 900 МиБ на том же сценарии.
- Видео: настоящий ffmpeg на синтетическом MKV H.264/AAC; MP4 seekable, хеш декодированного изображения совпадает, источник сохранён, кэш повторно используется. Проверены лимиты размера и диска. Статическая сборка ffmpeg в локальной ARM VM падает SIGILL; проверка выполнена совместимой Debian-сборкой. На production ffprobe отрабатывал успешно.
- Миграции: полная цепочка до `0095`, откат новой миграции и повторное применение проверены в отдельной локальной тестовой БД.
- Frontend: отправка сообщения, выбор пары, сравнение ответов при недоступном автоматическом расчёте, существующий сценарий подтверждения объединения и плеер каталога. TypeScript, ESLint, Ruff, Mypy.

Физическое воспроизведение в Telegram на iPhone после развёртывания ещё нужно проверить. На сервере файл не перепаковывался; подготовка начнётся при открытии записи после обновления приложения. Новых переменных окружения нет; NumPy добавлен в Poetry lock и hash-pinned requirements для сборки backend.
