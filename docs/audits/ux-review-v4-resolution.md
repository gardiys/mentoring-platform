# Исправления по UX/UI-ревью v4

Дата: 29 сентября 2026. Основание: [ревью](ux-review-v4-critique.md) и последующее
пожелание владельца разделить собеседования на самостоятельные страницы.
Изменения локальные, без коммитов и публикации. Серверная логика и API-контракты
этой работой не менялись; ранее внесённые изменения сохранены.

## Семь разделов собеседований

| Пункт меню               | Маршрут                                    |
| ------------------------ | ------------------------------------------ |
| Вопросы с собеседований  | `/interviews` — колоды, карточки и таблицы |
| AI-разборы собеседований | `/interviews/analysis`                     |
| Дневник собеседований    | `/interviews/journal`                      |
| Мок-собеседования        | `/interviews/mocks`                        |
| Резюме и легенда         | `/interviews/materials`                    |
| Каталог записей          | `/interviews/catalog`                      |

Каждая из пяти выделенных страниц запрашивает только свои данные. Моки, материалы
и личные AI-разборы доступны ученику; служебные разборы учеников остаются в
менторском разделе. Прямые ссылки на карточки, треки и разборы сохранены. Возврат
из трека ведёт в дневник, из личного разбора — в список AI-разборов. Для Mini App
новые разделы считаются корневыми страницами навигации.

## Уточнения к критике

- В текущей модели пять оценок, включая «Знаю отлично», поэтому буквальная сетка
  2×2 удалила бы рабочую функцию. Использована раскладка 3+2 без потери действий.
- После запроса владельца о семи разделах ограничение «не более девяти ссылок
  ученика» больше не применяется. Смысловые группы сохранены.
- Несколько названных «экранов без PageHeader» являются обёртками общих форм и
  уже имеют заголовок. Добавление ещё одного ухудшило бы семантику.
- У существующих светлых алиасов одного смысла (например, blue/brandBlue)
  намеренно общий токен. Различаются значения статусов, а не каждое имя цвета.
- Требование показать вопрос, ответ любой длины и оценки без прокрутки нельзя
  выполнить без скрытия части ответа. Короткая карточка помещается вместе с
  оценками после раскрытия; длинные ответы остаются полностью читаемыми.
- Отдельные коммиты не создавались: в проекте уже были незакоммиченные изменения,
  а владелец ведёт публикацию через свой Git-процесс.

## Проверки

Полный frontend-прогон: **46 файлов, 306 тестов — успешно**. После финальной
правки прокрутки дополнительно прошли тесты карточек и самостоятельных разделов.
TypeScript и production-сборка успешны. ESLint без ошибок; остаётся прежнее
предупреждение о зависимости useEffect в CareerPackageStaffPanel.

Браузер: проверено **120 комбинаций** (15 экранов × 2 темы × 4 ширины). Найденное
обрезание кнопки каталога на 768 px исправлено; повторные 16 проверок каталога и
тренировки прошли без замечаний. На 375×667 короткий вопрос, раскрытый ответ и
все пять оценок видны вместе после нажатия «Показать ответ»; сетка оценок 136 px.
Шесть медленных переключений очереди сохраняют положение фильтров. Ошибок
JavaScript и вспышек логотипа не обнаружено.

**440 проверок** состояний кнопок прошли без нарушений контраста. Проверка CSS
не обнаружила повторов селектора в одинаковом media-контексте между двумя
файлами стилей. Структура ранее изменённой сгенерированной API-схемы сохранена.

Браузерные скрипты используют только локальные тестовые API-ответы. Покрытие
ограничено указанными страницами в Chrome; другие браузеры не прогонялись.

- `docs/research/ui_brandbook_browser_audit.cjs`: 15 экранов, две темы,
  четыре ширины 320/375/768/1440 px; дополнительно медленные переходы очередей.
- `docs/research/ui_brandbook_controls_audit.cjs`: 11 цветов, пять вариантов,
  две темы, четыре состояния (обычное, hover, нажатие, disabled).
- Unit/integration: независимые запросы новых разделов, семь ссылок меню и
  единственное выделение, сохранение фильтров при загрузке, UUID-валидация,
  существующие сценарии карточек и дневника.
- TypeScript, ESLint, production-сборка. Проверки не затрагивают рабочие данные.
