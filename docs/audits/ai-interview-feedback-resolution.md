# Исправления по ревью AI-фидбека

29 сентября 2026. Основание: [исходное ревью](ai-interview-feedback-review.md).
Изменения локальные; рабочая база и AI-очередь не изменялись.

## Что подтвердилось

Итоговый отчёт действительно не получал речь кандидата. Корректность и подача
смешивались для HR-ответов, коммуникационные проценты не проверялись по источнику.
Кроме worker обнаружен второй пересчёт технических оценок в API: исправления
внесены в оба пути. Старые проценты коммуникации теперь не используются без
сохранённых проверяемых наблюдений.

## Решения по задачам

| Задача | Реализация |
| --- | --- |
| 1. Речь в сводке | `answer_excerpt` до 1200 символов, реальные UUID реплик, число слов, длительность интервала ответа, число дополнительных вопросов внутри этого интервала. Длительность может включать паузы и чужие реплики; счётчик не оценивает «сколько уточнений потребовалось» причинно. Эти признаки не используются как автоматический штраф. |
| 2. Независимая оценка подачи | `ReviewOutput.delivery_assessment`: HR/организационные ответы сохраняют `unable_to_assess` по фактической правильности, но могут иметь подтверждённые коммуникационные наблюдения. |
| 3. Проверка доказательств | Один общий код для worker, API и истории: цитата должна присутствовать в выделенном ответе и исходной реплике этого интервью; все UUID должны принадлежать ответу; ненадёжное авторство исключается. Без наблюдений процент `null`. Выводы и упражнения отклонённого ментором навыка исключаются из отчёта и динамики. |
| 4. Восемь навыков | Закрытый enum: structure, specificity, conciseness, clarification, handling_unknown, handling_pushback, reasoning_aloud, ownership. По одному подтверждённому примеру на навык. UI использует постоянные русские названия и ключи enum. |
| 5. Переформулировка | «Ты сказал / Лучше сказать так». Оригинал проверяется по источнику; новые числовые факты автоматически отбрасываются. Промпт запрещает выдумывать биографию, достижения, эмоции и мотивы. |
| 6. Приоритеты | До трёх коммуникационных действий из шести. Порядок зависит от оценки подтверждённого пробела; коммуникационное действие может быть первым. Действия коммуникации строятся из проверенных упражнений, а не свободной прозы сводки. |
| 7. Формат интервью | В review и summary передаются тип интервью, должность и направление. Разные ожидания для HR/скрининга, проектирования/кодинга, финала. Краткость сама по себе не считается преимуществом в проектировании. |
| 8. Доказательства в интерфейсе | Цитата, кнопка перехода к реальному таймкоду, объяснение основания рядом с процентом; ограничения вынесены на уровень всего отчёта. Неподтверждённые старые выводы скрываются. |
| 9. Динамика | Авторизованный API истории по ученику; блок у ученика в AI-разборах и у ментора в карточке ученика. Сравниваются одинаковые навыки в одинаковом формате интервью; показаны даты, изменение и повторение пробела в трёх наблюдениях. Отсутствие наблюдения не превращается в ноль. |
| 10. Практика | Упражнения с критериями находятся в отчёте и рядом с личными вопросами. Есть отметка выполнения, список выполненных и постепенная загрузка списка. Если AI не предложил упражнение для низкой оценки, используется задание по навыку, привязанное к исходной цитате. Выполнение не повышает AI-оценку автоматически. |
| 11. Вопросы работодателю | Отдельный результат извлечения и отдельное JSON-поле интервью; сохраняются проверенные ссылки на вопрос и ответ работодателя. Они отображаются в отчёте, не создают IntelligenceQuestion и не попадают в очередь карточек. Из вопросов не делаются выводы о личности или мотивации. |
| 12. Сложность и объём | Junior весит 2, middle/senior/unknown — 1. Для процента по теме и интервью нужны минимум три оценённых технических ответа. Провал junior + два верных senior даёт 50%, а не 67%. |
| 13. Текст технических тем | Сильные стороны и пробелы восстанавливаются из действующих review; сохранённые формулировки не могут добавить неподтверждённые пункты. Отклонённые оценки и заменённые ментором review не влияют на новый агрегат. |
| 14. Приоритет доказательств | Фактические ошибки идут первыми и сохраняются полностью; пункты с evidence выше пунктов без него. Затем недостающие понятия и прочие проблемы. |
| 15. Действия и материалы | В сводку передаётся короткий улучшенный ответ для слабых технических ответов. `related_topics` показываются как ссылки на поиск материалов и доступные колоды соответствующего направления. Действие ведёт к исходному вопросу; из вопроса можно добавить его в повторение. Повторное нажатие не создаёт дубль. |

Подтверждённая ручная техническая оценка ментора имеет приоритет над пометкой
ненадёжного автоматического выделения ответа. Коммуникационные наблюдения
по-прежнему требуют проверяемой исходной речи.

## Хранение и совместимость

- Миграция `20260929_0094`: `delivery_assessment` у review;
  `candidate_questions` и `coaching_state` у интервью. Пустые значения для старых записей.
- Прогресс и решения ментора привязаны к `analysis_revision`. Старая отметка
  не переносится автоматически на новый разбор; конкурентная запись старой версии даёт 409.
- Ученику доступна только своя история и выполнение своих упражнений; ментору —
  доступные ученики и направления; администратору — все. Отметку выполнения ставит ученик.
- Кнопка ручного добавления в повторение действует независимо от выключенной
  автоматической генерации личных вопросов. Общая публикация карточек не запускается.
- Версии extraction, technical review, light review, summary и compression повышены.
  Новые внешние AI-вызовы не добавлены: наблюдения создаются в существующем review.
  При сжатии сводки сохраняются исходные проверенные наблюдения, а не их пересказ моделью.
- Новые отчёты получают новый формат. Для старых нужна обычная кнопка повторного
  AI-разбора; автоматического массового платного пересчёта нет.

## Проверки и границы доказательства

Проверены фикстуры с HR-ответами, неверными UUID, цитатой интервьюера, отсутствующим
ответом, ошибками диаризации, выдуманными числами в переписанном ответе, отклонением
наблюдения ментором, малой технической выборкой и базовым пробелом. Интеграционные
проверки используют отдельную временную PostgreSQL; AI/транскрибация подменены.
Миграция проверена на применение, откат и повторное применение.

Результаты проверок:

- Backend: 135 тестов регрессионного набора; после последней правки — 21 тест
  grounding/compression, включая новый случай ручной оценки ментора.
  Всего 136 разных backend-тестов прошли.
- Frontend: 307 тестов в 46 файлах; после последних UI-правок повторно прошли
  все 7 тестов страницы разбора.
- TypeScript, ESLint изменённых файлов, Ruff и mypy шести модулей — без ошибок.
  Production-сборка frontend прошла.
- Браузер: отчёт и список разборов на ширинах 1440, 768, 375 и 320 px,
  синтетические данные с цитатами, упражнениями и тремя наблюдениями истории.
  Проверки не обнаружили ошибок JS, горизонтального переполнения,
  обрезанных кнопок и проблем контраста в проверенных состояниях.

При выкладке через обычный Git-процесс нужна миграция `20260929_0094`.
Новые переменные окружения не требуются. Внешние AI-запросы в ходе проверок
не выполнялись; реальная очередь обработки не запускалась.

Проверка ссылки и точной цитаты доказывает происхождение, но не семантическую
правильность психологического/педагогического вывода. Проверка чисел также не
может доказать отсутствие всех выдуманных фактов в переформулировке. Поэтому
сохранены запреты в промпте и добавлены решения ментора по каждому навыку.

Для навыка выбирается наиболее слабый подтверждённый пример; это ориентир
для практики, а не психометрический тест. История сравнивает такие наблюдения
по одинаковому типу интервью. Причины отказа работодателя не угадываются.

Слепая сверка 20 реальных разборов двумя интервьюерами из раздела 6 исходного
ревью не проводилась: это отдельное исследование качества с участием людей,
его нельзя заменить успешным прогоном автоматических тестов.
