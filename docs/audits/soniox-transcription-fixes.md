# Исправления по ревью Soniox — 1 октября 2026

Основание: [soniox-transcription-critique.md](soniox-transcription-critique.md).
Изменения сделаны локально; конфигурация production по умолчанию остаётся Nexara.

## Исправлено

| Замечание | Результат |
| --- | --- |
| 4.1: незаметная потеря диаризации | Отключение диаризации отклоняется до загрузки. В результате считаются спикеры и доля неатрибутированного текста. Один/ноль спикеров или превышение порога требуют явной проверки в UI и подтверждения через API. При нуле спикеров выбрать кандидата невозможно. |
| 4.2: фиктивный `unknown` | У реплики допустим `speaker_id=null`. Текст остаётся в расшифровке и AI-контексте, но не появляется как отдельный человек в выборе кандидата. Миграция переводит старые Soniox-реплики `unknown` в этот формат, сохраняет текст и рассчитывает предупреждение о качестве. |
| 4.3: очистка только после успеха | `cleanup` поддерживает завершённые и ошибочные задания, повторное удаление и 404. Журнал удалённых заданий хранится независимо от интервью. Sweeper повторяет очистку при старте и раз в 15 минут, включая локальные ошибки, исторические задания после пересчёта и удалённые интервью. Активные транскрипты до сохранения не удаляются. |
| 5.1: раздувание числа реплик | Смена метки на пунктуационном токене больше не создаёт новую реплику. Реальное короткое вмешательство другого говорящего сохраняется. |
| 5.2: чтение в event loop | Multipart загружается потоково, чтение с диска — через `anyio.open_file`, порциями 256 КиБ. В памяти не собирается весь файл. |
| 5.3: неявные пороги | Пауза и длительность настраиваются. Длинные монологи делятся на границе слова независимо от точки; части одного слова не разрываются. |
| 5.4: потеря confidence | Сохраняются агрегаты уверенности по реплике. Низкая уверенность добавляет неопределённость в контекст, аннотации и надёжность ответа. Она не интерпретируется как ошибка знаний кандидата. |
| 5.5: глоссарий | Канонические термины Python, Go и backend передаются в `context.terms`, без личных данных. |
| 5.6: инструменты сравнения | Добавлен офлайн CLI для WER, DER и частоты смен спикеров. Удалено повторное объявление `TRANSCRIPTION_PROVIDER` в локальном `.env`, сохранено последнее эффективное значение; секреты не выводились. |
| 6: диагностические неточности | 409 обозначен как конфликт состояния; происхождение длительности сохраняется; connectivity check проверяет async-режим и языки. Есть отдельный лимит размера Soniox-загрузки. |

Поддержка Nexara, явного HTTP(S)-прокси и закрепление уже отправленных заданий за исходным провайдером сохранены.

## Границы решения

- В `/models` нет признака поддержки диаризации. Нельзя достоверно проверить её наличие таким запросом: проверяется фактический результат транскрибации. Формат сверялся с официальной OpenAPI Soniox; глоссарий — с [документацией context](https://soniox.com/docs/stt/concepts/context).
- Короткая последовательность A→B→A сама по себе не доказывает ошибку диаризации. Автоматическое переназначение произнесённых слов может приписать кандидату подсказку. Сглажена только пунктуация; краткие произнесённые реплики не переатрибутируются.
- Пороги confidence и доли неизвестного спикера — консервативные начальные настройки, не измеренные значения точности. `extra=ignore` оставлен для совместимости API; confidence читается явно, аудиособытия не становятся речью.
- Sweeper восстанавливает очистку **известных локально ID**. Неоднозначная загрузка/отправка, при которой удалённый объект создан, но ответ с ID потерян до записи в БД, остаётся ограничением. Удалять весь проект Soniox по возрасту опасно: в нём могут быть записи других приложений. Нужна отдельная сверка таких объектов в Console.
- Реальное сравнение провайдеров ещё не проведено: нет проверенного вручную корпуса с эталонным текстом и спикерами. Тестовые фразы не являются доказательством превосходства Soniox. CLI готов, формат описан в README; платные транскрибации не запускались.
- Извлечение аудио из видео не включено. Перед включением нужно проверить длительность, начальное смещение и соответствие таймкодов исходному видео, особенно при нескольких дорожках. Это отдельная оптимизация передачи данных, без доказанного здесь снижения стоимости распознавания.
- В исходном ревью указано раскрытие Soniox-ключа в другой сессии. Этот ключ не выводился и не менялся в рамках исправлений; его ротация выполняется владельцем в Console.

## Развёртывание

Нужна миграция `20261001_0096` перед запуском обновлённых backend/worker.
Настройки имеют значения по умолчанию: новые переменные `.env.production` обязательными не стали.
После переключения на Nexara Soniox-ключ необходимо сохранить до завершения фоновой очистки.
Миграция не допускает откат с потерей реплик: обратное `NOT NULL` потребует сначала разрешить
неатрибутированные реплики, если они уже есть в базе.

## Проверки

- 47 unit/config/benchmark-тестов, без запросов к платному API.
- 9 UI-тестов страницы AI-разбора, включая запрет продолжения без проверки диаризации.
- Интеграционные сценарии PostgreSQL: сохранение неизвестного спикера, подтверждение качества,
  повтор очистки после ошибки, защита активного задания, переключение провайдера,
  ручной повтор после очистки. Проверены регрессии API, очереди и перезапуска AI-разбора.
- Alembic upgrade на отдельной временной БД; преобразование старого `unknown` проверено
  отдельным тестом на заполненной базе. Временная БД после проверки удалена.
- Ruff, mypy, TypeScript, Compose config и `git diff --check`.

## Дополнение: повтор после пополнения баланса

На локальном разборе Selectel обнаружено, что повтор опрашивал старое терминальное
задание `organization_balance_exhausted`, не создавая нового. Теперь ошибки завершённых
заданий имеют отдельные коды (`TRANSCRIPTION_JOB_BALANCE_ERROR`, `TRANSCRIPTION_JOB_FAILED`),
а явный ручной повтор создаёт новую отправку без ожидания sweeper. Для старых записей
предусмотрено распознавание точной сохранённой диагностики прежнего адаптера. Сетевой сбой
сохраняет прежний job ID и не вызывает повторную платную отправку. Проверки: 42 теста
адаптера и 14 интеграционных тестов качества, очистки и повторов; Ruff и mypy прошли.

## Дополнение: nullable `is_audio_event`

На реальном завершённом ответе Soniox поле `is_audio_event` оказалось равным `null`
во всех 1338 токенах. Прежний тип `bool` отклонял весь результат. Тип исправлен на
`bool | None`: null/отсутствующее поле сохраняют речь, true исключает аудиособытие.
Добавлен регрессионный тест полного `get_result`; 43 теста адаптера прошли, как и mypy/Ruff.
Локальный разбор Selectel восстановлен из того же задания: сохранено 65 реплик, определены
два спикера, статус — выбор кандидата. Повторная платная транскрибация не запускалась.
