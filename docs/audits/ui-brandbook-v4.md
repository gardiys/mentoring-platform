# UX/UI-аудит после брендбука v4

Дата: 29 сентября 2026. Изменения в локальном проекте, без публикации на сервер.

## Исправления по обратной связи

- Удалён блок «Геральт рядом» из бокового меню. Маскот убран с обеих форм входа.
- Буква «П» в favicon и знаке переведена в SVG-контур Unbounded 800. Рендеринг
  не зависит от загрузки шрифта; версия URL favicon обновлена для сброса кэша.
- Подписи и интервалы повторения в кнопках оценки карточки наследуют контрастный
  цвет кнопки. Убраны тусклые второстепенные подписи на яркой подложке.
- В главном синем блоке роадмапов весь текст теперь белый. Градиент затемнён
  до `#246DCC` → `#174B9C`, чтобы небольшой текст тоже оставался читаемым.
- Убран логотип из общего LoadingState: при первой загрузке разделов больше
  не появляется дополнительный знак. Небольшой индикатор показывается через
  200 мс, место под него выделяется сразу. Индикатор перехода между маршрутами
  также отложен, поэтому быстрые переходы не дают краткой вспышки.
- В «Разборах интервью» смена статуса больше не заменяет всю страницу загрузчиком.
  Заголовок, состояние обработчиков и фильтры остаются на месте; загрузка или
  ошибка отображаются внутри списка. Данные другого статуса не подставляются
  под выбранный фильтр. Фоновое обновление не добавляет строку в поток документа.

## Проверки

- TypeScript и production-сборка Vite.
- Полный набор frontend-тестов: 45 файлов, 298 тестов. В том числе сохранение
  фильтров при медленной загрузке/ошибке и отсутствие устаревших карточек под новым
  статусом, мобильная навигация и вход клавишей Enter.
- ESLint: без ошибок; остаётся прежнее предупреждение о зависимости useEffect
  в `CareerPackageStaffPanel.tsx`.
- Chrome: 9 экранов × 2 темы × 4 ширины (320, 375, 768, 1440 px) = 72 комбинации.
  Проверены переполнение страницы, обрезка текста кнопок, контраст, favicon 16 px,
  клавиатурное закрытие меню и отсутствие логотипа в загрузчиках.
- Отдельно: 9 цветов × 5 вариантов кнопки × 2 темы × 3 состояния
  (обычное, hover, нажатие) = 270 проверок контраста и границ.
- Переключение трёх новых очередей на desktop/mobile с искусственной задержкой API
  700 мс: положение фильтров до, во время и после запроса, отсутствие вспышки логотипа.

Проверки выполняются на тестовых API-ответах из репозитория. Они не отправляют
запросы изменения данных на рабочий сервер. Покрытие ограничено указанными
экранами в Chrome; это не утверждение о проверке всех браузеров и страниц.

Результат: все перечисленные проверки прошли. В 72 комбинациях экранов нет
горизонтального переполнения, обрезанных подписей кнопок или выявленных нарушений
контраста. Все 6 переходов между очередями сохранили положение фильтров;
вспышек логотипа и ошибок JavaScript не обнаружено.

## Повторный запуск браузерных проверок

Запустить локальный frontend на `http://127.0.0.1:5173` и выполнить из корня:

```sh
node docs/research/ui_brandbook_browser_audit.cjs
node docs/research/ui_brandbook_controls_audit.cjs
```

Нужны установленный Playwright и Chromium. Если Playwright установлен в другом
локальном проекте, `PLAYWRIGHT_MODULE_PATH` указывает абсолютный путь к пакету.
`CHROME_BIN` позволяет использовать установленный Chrome. `UI_AUDIT_URL` меняет
адрес frontend; `UI_AUDIT_OUTPUT_DIR` — каталог результатов. По умолчанию JSON
и screenshots сохраняются в `mentoring-ui-audit` внутри временного каталога ОС.
При найденной проблеме скрипты завершаются ненулевым кодом.
