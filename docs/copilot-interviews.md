# Треки, записи и использование Copilot

Реализация: 9 сентября 2026. Изменения нужны в обоих проектах; production автоматически не обновляется.

## Для ученика

- Запись MP4 включена по умолчанию. Если её отключить, выбор запоминается.
- В реальном интервью при входе через платформу нужно выбрать активный трек компании того же направления Python/Go или создать новый. В тренировке такого поля нет.
- У трека можно указать команду, вакансию и заметки о компании/отборе. Для существующего трека эти поля редактируются на странице трека платформы.
- Copilot учитывает предыдущие этапы выбранного трека: описания и доступный фидбек ментора/AI. История участвует в подсказках, если включено использование истории интервью. Полные старые видео не пересылаются модели.
- Опыт других учеников берётся только из уже доступного пользователю каталога: та же компания, направление, явно указанная команда и тип этапа; если указана вакансия, она тоже должна совпадать. Без команды чужой опыт не добавляется. Скрытые описания анонимных авторов не раскрываются. Эти примеры — фон, а не предсказание вопросов или личный опыт кандидата.
- После завершения нажми «Загрузить собеседование на платформу». Укажи тип этапа, дату/время и описание — те же поля, что в форме создания этапа платформы. Выбери связанную запись или MP4 с компьютера. В треке создаётся один этап с этой записью.
- «Мои интервью с Copilot» показывает историю, активное время и статус загрузки. Можно вернуться к записи позже, в том числе после перезапуска приложения.
- Загрузка продолжается при закрытии её формы; при выходе из приложения приостанавливается. Повторный запуск загрузки использует подтверждённые части и тот же этап. После истечения адресов хранилища или изменения файла передача начнётся заново; этап не дублируется.

Локальный режим с DEV_ACCESS_TOKEN сохраняет запись и историю, но не выдаёт доступ к чужому аккаунту платформы. Треки и загрузка требуют входа через платформу.

## Настройка серверов и доступ

1. Обновить backend и frontend платформы, применить миграцию `20260908_0085`.
2. Задать случайный серверный секрет: `COPILOT_INTEGRATION_TOKEN` в env платформы и **то же значение** `PLATFORM_INTEGRATION_TOKEN` в env Copilot. Генерация: `openssl rand -hex 32`. Секрет не передаётся в Electron или браузер и не является ключом OpenAI.
3. Обновить Copilot API; миграция `20260908_platform_interviews` применяется обычным процессом запуска. Production использует `AUTH_MODE=platform`.
4. Для запуска на учениках установить `COPILOT_STUDENTS_ENABLED=true` в env платформы и пересоздать backend. По умолчанию `false`: ученики по-прежнему не допущены. Даже с `true` доступ есть только у активного ученика со статусом `interviewing` — «Ходит на собеседования».
5. Установить новую сборку Copilot. Старые API платформы без `/api/v1/copilot/access` потребуют обновления вместо обхода проверки.

Проверка статуса применяется к скачиванию сборок, выдаче desktop-токена, запросам с уже выданным токеном и Copilot API. Активный WebSocket перепроверяет доступ раз в минуту; при отзыве ставится на паузу и закрывается.

## Администратору

На платформе в разделе Copilot находится таблица учеников: завершённые интервью (реальные/тренировки отдельно), число начатых сессий, суммарное активное время и последний запуск. Доступ к статистике есть только у админа.

Время считает Copilot API по подтверждённому соединению, исключая паузы и отключение. Снимки счётчиков отправляются платформе каждые 15 секунд с повтором после ошибок, вне цикла обслуживания интервью. Абсолютные суммы и ревизии защищают от двойного учёта повторных/переставленных запросов. Потеря последних секунд при аварийном завершении сервера возможна; это статистика использования, не финансовый биллинг.

Метаданные истории и счётчики не удаляются вместе с расшифровкой по retention или кнопке удаления данных сессии. Локальный MP4 хранится независимо. Для сессий, существовавших до миграции, активное время равно 0: достоверно восстановить его задним числом нельзя.

## Технические границы

- MP4 передаётся напрямую из main process Electron в существующее multipart-хранилище платформы. Copilot API получает только поля этапа и метаданные. Полный файл не загружается в память и не идёт в OpenAI.
- Применяются существующие права владения, ограничения редактирования этапов, проверки multipart-токена/размера и лимит видео платформы (2 ГБ). Доступ к хранилищу и стоимость обработки/AI-разбора на платформе настраиваются самой платформой.
- Контекст компании кэшируется в памяти не более минуты. При недоступности платформы его получение ограничено двумя секундами и не обрывает живую подсказку.
- Привязка локальных файлов разделена по адресу API и аккаунту. Старые записи без привязки можно выбрать вручную. Возобновление multipart хранится локально через защищённое хранилище ОС.
- Для старых сессий без выбранного трека автоматическая загрузка недоступна; их MP4 можно добавить обычным способом на платформе.

## Проверки

- Backend Copilot: история и удаление расшифровки, учёт пауз/переподключений, повторная отправка счётчиков, обязательный трек в реальном режиме, владение и relay загрузки.
- Backend платформы: закрытый rollout, канонический статус ученика, отзыв старого desktop-токена, доступ админа, фильтрация команд/вакансий/анонимных авторов, идемпотентные этап/MP4. Регрессия существующего журнала и каталога.
- Electron: фактическая потоковая передача синтетического файла, продолжение после сбоя/перезапуска, повтор завершения, разделение файлов разных аккаунтов.
- Сквозной интерфейс: `node scripts/audio_ui_review.mjs --platform`, в сборке `node scripts/packaged_smoke.mjs --platform`. Доказательства: `platform-ui-review.json` и `docs/screenshots/interview-platform-history.png` в репозитории Copilot.
- Запись: синтетические экран/два аудиосигнала, переключение экрана, пауза, разрыв сети, финализация и воспроизведение MP4 средствами macOS. Реальный двухчасовой звонок и запуск на Windows вручную не проверялись.
